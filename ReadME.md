## Run order (from the project root)

Datasets (`data/samples/*.csv`, `data/processed/*.csv`) and trained models
(`saved_models/*.joblib`) are **not committed**. They are regenerated by the
scripts below (all sampling uses fixed seeds).

```powershell
python .\src\data_generation\generate_samples.py         # 4 x 10,000 uniform input samples (seed 2026)
python .\src\data_generation\generate_edge_samples.py    # 4 x 6,000 supplementary rail-edge samples (seed 2028)
python .\src\data_generation\generate_rail_samples.py    # 4 x 10,000 supplementary rail-corner samples (seed 2029)
python .\src\spice\run_dataset.py                        # simulate -> data/processed/{case}.csv
python .\src\spice\run_dataset.py --suffix _edge         # simulate -> data/processed/{case}_edge.csv
python .\src\spice\run_dataset.py --suffix _rail         # simulate -> data/processed/{case}_rail.csv
python .\src\analysis\data_check.py                      # Kirchhoff check + 3 trend plots
python .\train_models.py                                   # train, compare, select, test, save (~2 h on 8 cores)
python .\src\validation\gate_validation.py --corners 200 --reuse-spice
python .\src\validation\circuit_validation.py --reuse-spice
```

* `run_dataset.py` runs simulations in parallel (`--workers N`, `--cases nmos_on pmos_off ...`).
  The output does not depend on the worker count.
* The ngspice executable is taken from `--ngspice`, the `NGSPICE` environment variable,
  `ngspice` on `PATH`, or `ngspice_con.exe`, in that order.
* `--reuse-spice` re-scores new models against the cached SPICE results in `results/`.
  Drop it to re-run the 3,600 gate / 51,200 circuit simulations.
* `train_models.py` options (environment variables):
  * `TRAIN_CASES=pmos_off,nmos_on` retrains only those cases.
  * `REUSE_FITS=1` re-runs only selection/testing, from the fit cache in `data/training_cache/`.
  * `MLP_SEEDS=3` averages several MLP seeds.
  * `USE_EDGE_SAMPLES=0` and `USE_RAIL_SAMPLES=0` train without the supplementary sets.

## Models we are trying out

Model	             Why try it?
Random Forest	     Reliable baseline; handles nonlinearities
Extra Trees	         Often effective for complex transistor behavior
Gradient Boosting	 Can model nonlinear relationships accurately
MLP Neural Network	 Can learn smooth nonlinear functions

Data Split Used : 70+15+15, seed 42 (train_models.py contains splitting, training and selection).
The uniform, edge and rail datasets are each split separately and then combined,
so the uniform split matches the original one.

IMPORTANT (should include in the report)
* Errors are floor-adjusted relative errors, `|pred - true| / max(|true|, 1e-18 A) * 100`.
  1e-18 A is the SPICE `abstol`, below which currents are not resolved.
* Test-set results are reported only after model selection on validation data.
* Accuracy = `100 - error`, clipped at 0, averaged over all 3,600 gate cases.
* The edge and rail datasets deviate from the uniform Vd/Vs specification (see 5 below).

## Modelling method (shared code in `src/transistor_ml.py`)

1. **Targets**: `log10(|I| + 1e-21)` per terminal current. The sign of each terminal
   is constant where the training data agrees on it, otherwise it is predicted by
   a gradient-boosting classifier.
2. **Features**:
   * The 12 inputs, plus Vgs, Vds, Vbs, Vgd, Vbd and Vgb.
   * A BSIM4-style effective threshold (body effect, temperature via `kt1`, DIBL via `eta0`)
     and the subthreshold overdrive `(Vgs - Vth_eff)/(n kT/q)`.
   * log10 of an EKV channel-current estimate, oxide-field proxies, log10(W) and 1/T.
   * **Gate-tunnelling estimates**: log10 of the BSIM4 Igc/Igb expressions for Vgs, Vgd
     and Vgb, using the fixed tunnelling constants of the 16nm LP card.
   * The raw vd, vs and a swap flag.
3. **Two target frames**: "raw" (netlist terminals) and "canonical" (drain/source
   relabelled so Vds >= 0 for NMOS, Vsd >= 0 for PMOS). Both are trained, because
   the 16nm LP card is not drain/source symmetric.
4. **One model per terminal current, selected per terminal**:
   * Every family is trained in both frames. For each terminal, the (frame, model) with
     the lowest validation P95 error is selected.
   * The MLP is a separate 64x64x64 tanh network per terminal current, trained with
     full-batch L-BFGS (`PerTerminalRegressor`). The MLP is selected for all 16 terminals.
   * **Unresolved currents**: some samples give currents below SPICE's `abstol`, often
     exactly 0 A (e.g. PMOS OFF `ig`/`ib` with a terminal on the gate/body rail).
     Each terminal network ignores those samples when training, unless they are the
     majority. The selection P95 is computed over currents >= 1e-16 A
     (`p95_resolved_error_percent`), falling back to plain P95.
5. **Supplementary samples near the rails.** Inside a gate, every transistor has Vd and
   Vs at (or within microvolts of) 0 or VDD, and uniform sampling almost never visits
   those points. Two extra sets draw every parameter as in the spec, except Vd and Vs:
   * `generate_edge_samples.py`, 6,000 per case: Vd/Vs exactly at 0 or VDD (25% each),
     within 1e-9 to 1e-2·VDD of a rail (15% each side), or uniform (10%).
   * `generate_rail_samples.py`, 10,000 per case: each of Vd/Vs exactly on a rail (45%),
     within 1e-9 to 1e-3·VDD of a rail (35%), or uniform (20%).

   No gate-level SPICE results are used to build training data.
   **This deviates from the uniform Vd/Vs spec and should be stated in the report.**

## Gate-level validation

[`src/validation/gate_validation.py`](src/validation/gate_validation.py) simulates
INV, NAND2, NOR2, AND2 and OR2 as complete static-CMOS netlists for all 18 input
cases at 200 PVT corners (corner seed 7, 3,600 SPICE runs; Wn = 2·Lmin, Wp = 4·Lmin).

ML leakage:
1. The SPICE node voltages give every transistor's Vd, Vs and Vb. The gate voltage is
   snapped to its logic level (0 or VDD), and ON/OFF follows from that logic level.
2. ON transistors in a gate sit at |Vds| ~ 1 µV, where their channel current is a tiny
   residual no regression can resolve. So ON devices contribute only their
   predicted `ig` and `ib`. Their channel currents are solved from Kirchhoff's law at the
   internal nodes, using the OFF devices' predicted currents.
3. Leakage = |sum of terminal currents at the VDD node|.

Check: feeding exact single-transistor SPICE currents into this procedure
reproduces the gate SPICE leakage with a 0.0008% median error, so the
remaining error comes from the transistor models alone.

### Fixes compared with the earlier gate validation

| Problem | Effect |
|---|---|
| 1 MΩ `Rbias` resistors on internal nodes | "SPICE leakage" in 9 rows was the resistor current (e.g. NAND2 `10` = V(x)/1 MΩ exactly), and logic levels were wrong |
| OR2 netlist: NOR-stage PMOS drained into `out` instead of `z` | OR2 was not an OR gate (z = 0.32 V for `00`) |
| ON/OFF decided by exact float `vg == vdd`; internal gate voltage passed through | AND2/OR2 inverter devices were misclassified and given out-of-training gate voltages |
| Leakage summed from ON devices at Vds ≈ 1 µV | ~10^5 % errors (INV `0`, NAND2 `00`/`01`, AND2/OR2 `11`) |
| W = Lmin (edge of the training range) | Replaced by Wn = 2·Lmin, Wp = 4·Lmin |

Progression of the mean gate accuracy:

| Version | Mean accuracy |
|---|---:|
| Original | ≈ 0% (median errors up to 5×10^5 %) |
| Fixed validation + new targets/features/MLP | 81.4% |
| + rail-edge samples | 94.9% |

| Per-terminal MLPs + tunnelling features + rail-corner samples | 98.56% |
| + unresolved-current handling | **98.77%** |

### What limits the accuracy

Each gate transistor was also simulated on its own in SPICE at its exact in-gate bias
(diagnosis only, never used for training). A 1% perturbation test with these currents
shows which device currents set the gate leakage:
* PMOS ON `ig` (Vd = Vs = Vb = VDD, Vg = 0): about 1:1 in almost every gate.
* PMOS OFF `is`: INV `1`, NAND2 `11`, NOR2 `10`.
* PMOS OFF `ib`: NOR2 `11`.
* NMOS ON `ig`: AND2 and OR2.
* NMOS OFF currents barely matter for this card.

### Remaining gap to 99%

* **Unconverged SPICE references.** About 11 AND2 cases in `gate_spice_raw.csv` are not
  converged operating points: Newton, gmin and source stepping fail, and ngspice's
  transient-op fallback stops before the circuit settles. Example: AND2 `00`, corner 148.
  * The cache has 3.74e-9 A. The same circuit with 0 V ammeters, or a long transient,
    gives 1.92e-10 A, which matches the per-transistor reconstruction.
  * These points alone cost about 0.25 percentage points (AND2 `00`/`10`).
* **NOR2 `11`** (96.6%): PMOS OFF `ib`/`is` with the drain at the internal node
  (≈ 0.9·VDD) still has 3–8% error. More stacked-device samples should help.
* **PMOS ON `ig`** (about 0.8% median error at gate biases) caps most gates near 99.1–99.2%.
  A seed ensemble (`MLP_SEEDS=3`) may lower it.
